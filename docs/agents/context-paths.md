# Context path scenarios

This matrix is the behavioral acceptance seam for the repository's information
architecture. Review a context change by following each applicable scenario from the
resident surface through the triggered pointers, then confirm that the listed unrelated
branches stay out. The matrix records expected behavior; local pointers remain the
distributed index.

Documents are named by role rather than by headings or line positions. A rename updates
the link without changing the scenario. Document size is diagnostic evidence, never an
acceptance limit.

The matrix records the routed authorities after each split. Review new pointers by
adding the smallest scenario that distinguishes their context load.
Historical evidence is conditional in every production scenario and loads only when the
current contract or measurement needs provenance.

When auditing this information architecture or remeasuring a route, read
[Context-path evidence](context-evidence.md). It records the completed scenario review
and reproducible before/after measurements; it is not part of a normal task path.
